# PAM Player Manual (`pam_player.py`)

## Purpose

`pam_player.py` is the Manim scene runner for PAM JSON screenplays. It reads a JSON array of action objects, builds characters and props, plays the scene sequentially, and optionally drives camera motion from Fountain-generated prompt metadata.

The key architectural point is this:

**`pam_player.py` does not define its own argparse-style command-line flags.**
You run it through **Manim’s CLI**, and you control PAM-specific behavior mainly with **environment variables**.

---

## 1. How to run it

### Direct Manim invocation

```bash
manim -pql pam_player.py PAMPlayer
```

This renders the `PAMPlayer` scene class from `pam_player.py`.

### Use a specific screenplay JSON

```bash
PAM_SCRIPT=my_scene.json manim -pql pam_player.py PAMPlayer
```

### Show the render-time clock

```bash
PAM_SCRIPT=my_scene.json PAM_SHOW_CLOCK=1 manim -pql pam_player.py PAMPlayer
```

### Disable camera mode

```bash
PAM_CAMERA_MODE=0 PAM_SCRIPT=my_scene.json manim -pql pam_player.py PAMPlayer
```

### Supply an explicit prompts JSON for camera-mode

```bash
PAM_CAMERA_MODE=1 PAM_SCRIPT=my_scene.json PAM_PROMPTS=my_scene_prompts.json manim -pql pam_player.py PAMPlayer
```

---

## 2. What is the actual CLI surface?

There are **two layers** of runtime control.

### Layer A: Manim CLI arguments

These are not defined by PAM; they come from Manim.

Typical pattern:

```bash
manim [MANIM OPTIONS] pam_player.py PAMPlayer
```

Common examples:

- `-p` — preview after render
- `-ql` — low quality
- `-qm` — medium quality
- `-qh` — high quality
- `-qk` — 4K

So in practice, the true operator-facing command is a combination of:

1. **Manim flags**
2. **PAM environment variables**
3. the script file `pam_player.py`
4. the scene name `PAMPlayer`

### Layer B: PAM-specific environment variables

These are the real `pam_player.py` runtime parameters.

---

## 3. PAM-specific runtime parameters

## `PAM_SCRIPT`

**Purpose:** path to the PAM JSON screenplay file.

**Default:**

```text
screenplay.json
```

**Example:**

```bash
PAM_SCRIPT=episode_01.json manim -pql pam_player.py PAMPlayer
```

**What it affects:**
- which JSON file is loaded into `actions`
- all scene content, cast, props, dialogue, camera markers, captions, and timing

**Failure mode:** if the file does not exist or is invalid JSON, the render will fail when `pam_player.py` tries to open or parse it.

---

## `PAM_CAMERA_MODE`

**Purpose:** enable or disable automatic camera behavior.

**Default behavior in code:** effectively **on by default**.

The player uses:

```python
bool(os.environ.get("PAM_CAMERA_MODE", "1"))
```

So if the variable is absent, camera mode is treated as enabled.

### Important caveat
Because the code uses Python `bool()` on the environment string, **any non-empty string is truthy**. That means:

- `PAM_CAMERA_MODE=1` → on
- `PAM_CAMERA_MODE=true` → on
- `PAM_CAMERA_MODE=0` → **also truthy in pure Python terms** unless you explicitly rely on the code path/documented intent

The documentation intends `0` to mean off, but the implementation uses `bool(string)` rather than a strict parser. If you want this behavior to be completely robust, the code would ideally parse values explicitly.

### Operational intent
When enabled, the player:

- loads prompt metadata from `PAM_PROMPTS` or the auto-derived prompts path
- watches `_subscene_marker` entries in the PAM JSON
- applies or queues camera moves based on `shot_meta`

### When disabled
The scene still renders, but the automatic camera system is bypassed.

---

## `PAM_PROMPTS`

**Purpose:** path to the prompts JSON file generated by `fountain2pam.py`.

**Used only when camera mode is active.**

**Default:** auto-derived from `PAM_SCRIPT` by replacing `.json` with `_prompts.json`.

Example:

- `PAM_SCRIPT=scene.json`
- default prompts path becomes `scene_prompts.json`

**Example explicit use:**

```bash
PAM_CAMERA_MODE=1 PAM_SCRIPT=scene.json PAM_PROMPTS=scene_prompts.json manim -pql pam_player.py PAMPlayer
```

**If the prompts file is missing:**
- the player prints a message
- camera mode remains on
- it falls back to inline `_shot_meta` stored directly on `_subscene_marker` actions

This fallback is useful when the screenplay JSON already embeds camera metadata.

---

## `PAM_SHOW_CLOCK`

**Purpose:** show a live render-time clock in the upper-right area of the frame.

**Default:** off.

**Effect:** displays elapsed render time in `M:SS.ss` format.

**Recommended use:** low-quality preview renders only.

**Example:**

```bash
PAM_SCRIPT=scene.json PAM_SHOW_CLOCK=1 manim -pql pam_player.py PAMPlayer
```

**What it does not affect:**
- scene timing logic
- animation behavior
- JSON parsing
- output semantics

It is strictly an on-screen diagnostic overlay.

```bash
PAM_CAMERA_MODE=0 PAM_SCRIPT=scene.json manim -pql pam_player.py PAMPlayer
```

## 5. Relationship to `pam-render`

The README also mentions a shell wrapper named `pam-render`.

That wrapper is the place where you get a more traditional flag-based CLI such as:

```bash
./pam-render --script screenplay.json --output my_animation --quality l
```

and optionally:

```bash
./pam-render --script screenplay.json --show-clock
```

So:

- **`pam_player.py` itself** = Manim scene + environment variables
- **`pam-render`** = convenience wrapper with operator-friendly flags

If you are documenting “CLI arguments,” distinguish these two clearly.

## 6. What `construct()` does at runtime

Inside `PAMPlayer.construct()`, the sequence is roughly:

1. Set the background color.
2. Read `PAM_SCRIPT` and load the JSON action list.
3. If camera mode is on, load prompts JSON and build a `subscene_id -> shot_meta` lookup.
4. Consume and render an initial `title` action if present.
5. Consume and render one `persistent_caption` action if present.
6. Enable the optional clock if `PAM_SHOW_CLOCK` is set.
7. Initialize registries for cast, props, scene objects, and zones.
8. Reset the camera to a wide shot at scene start when camera mode is active.
9. Iterate through the remaining JSON actions in order.
10. Clean up persistent caption, title, subtitle, and clock at the end.

This is useful to know because some actions are treated specially before the main loop.

## 7. Screenplay structure

The screenplay file is a **JSON array of action objects**.

Example skeleton:

```json
[
  {"action": "title", "text": "Scene 1", "subtitle": "Lobby"},
  {"action": "cast", "characters": {
    "alice": {"build": "narrow", "offset": [-3, 0, 0]}
  }},
  {"action": "fade_in", "who": "alice"},
  {"action": "say", "who": "alice", "text": "Hello."},
  {"action": "fade_out", "who": "alice"}
]
```

Objects containing only `_comment` or `_hint` are skipped.

## 8. Special top-level actions handled directly by `pam_player.py`

These actions are not merely delegated; the player itself owns their logic.

## `title`

Used only if it is the **first action** in the screenplay.

### Keys
- `text` — main title text
- `subtitle` — optional subtitle line
- `y_offset` — top-edge buffer used when placing the title

### Example

```json
{"action": "title", "text": "Act I", "subtitle": "Observatory"}
```

---

## `persistent_caption`

A static caption bar that remains visible for the full scene.

### Keys
- `text` — required caption text
- `position` — `bottom`, `lower-third`, or `top`
- `style` — `normal`, `italic`, or `bold`
- `font_size` — integer, default 16

### Notes
- only the first such action is consumed at startup
- it is removed from the normal action stream
- it does not block the rest of the scene

---

## `_subscene_marker`

A synchronization marker used by camera mode.

### Keys
- `_subscene_marker` — subscene id string
- `_shot_meta` — optional inline shot metadata
- `bg_color` — optional background color override
- `zone` — optional spatial zone name

### What it does
Depending on the `move` field in shot metadata, the player may:

- apply an immediate static cut
- defer a camera move until the next bubble appears
- execute `pan-up`
- execute `pan-down`
- execute `descend`
- execute `push-into`

This is the core of automatic camera sync.

---

## `cast`

Declares cast members before they are faded in.

### Required shape

```json
{
  "action": "cast",
  "characters": {
    "alice": {...},
    "bob": {...}
  }
}
```

### Character keys
- `figure_type` — `human`, `alien`, `dog`, or `dodecahedron`
- `pose` — initial pose name
- `offset` — `[x, y, z]`
- `style` — style dict
- `build` — body build, usually `default`, `narrow`, `broad`, `alien`
- `scale` — dict with `sx`, `sy`, `anchor`
- `color` — color hex
- `torso_color` — second color for torso zone
- `gender` — figure-dependent preset
- `spawn` — spawn metadata for prop-characters

### Important note
`cast` registers characters, but does **not** draw them. Rendering happens on later `fade_in` actions.

---

## `fade_in`

Creates the figure if needed and animates it into the scene.

### Keys
- `who` — character key
- `pose` — optional override of starting pose
- `offset` — optional override of position
- `style` — style dict
- `build` — build override
- `figure_type` — `human`, `alien`, or `dog`
- `scale` — optional scaling spec
- `gender` — optional gender preset
- `torso_color` — optional torso color override
- `duration` or `rt` — fade timing

### Notes
- if a `cast` block exists, `fade_in` can inherit from it
- for dogs, fade timing uses dog-specific fade parameters

---

## `say`

Character speech bubble.

### Keys
- `who` — speaker
- `text` — required dialogue text
- `hold` — bubble hold time, default 1.2
- `font_size` — default 20
- `side` — bubble side, default `right`
- `style` — `normal`, `os`, or `phone`

### Notes
- consumes any deferred camera move so the camera can move together with the bubble fade-in
- `style="os"` uses the off-screen/phone bubble variant

---

## `wave`

Arm-lift plus wag action.

### Keys
- `who` — character name
- `hand` — `right` or `left`
- `cycles` — wag count, default 2
- `rt_lift` — raise/lower time, default 0.4
- `rt_wag` — per-wag keyframe time, default 0.24

---

## `scene_props`

Opening-stage prop declaration. Functionally similar to `props`, but intended for the initial stage layout.

### Keys
- `items` — dict of prop specs
- `rt` — fade-in time for built props

### Per-item prop keys
At minimum, each item usually includes:
- `type`
- `x`
- optionally `y`, `color`, `label`, `height`, `parent`, `attach`, `attrs`, `hidden`

### Notes
- child props are built after parents
- hidden props are registered but not shown until later

---

## `scene_objects`

Background dressing that the camera can target without treating them as interactive props.

### Keys
- `items` — dict of scene object specs
- `rt` — fade-in time

### Typical per-item fields
- `type`
- `x`
- `y`
- `color`
- `label`
- `height`

### Notes
- stored separately from interactive props
- usable as camera `SUBJECT` values
- backdrops are pushed behind everything else

---

## `zones`

Declares named horizontal regions for camera clamping.

### Keys
- `items` — dict of zone specs

### Per-zone keys
- `x_min`
- `x_max`
- `label`

### Notes
A later `_subscene_marker` can activate the zone by name.

---

## `props`

Mid-scene or general prop batch declaration.

### Keys
- `items` — dict of prop specs
- `rt` — fade-in time

It uses the same prop-building machinery as `scene_props`.

---

## `reparent_prop`

Move a prop to a new parent, or release it to world coordinates.

### Keys
- `prop` — required prop name
- `parent` — new parent name or `null`
- `attach` — attachment point, default `surface`
- `x` — world x when releasing to world
- `y` — world y when releasing to world
- `rt` — animation time, default 0.3

---

## `remove_prop`

Fade or instantly remove a prop.

### Keys
- `prop` — prop name
- `rt` — fade-out time; if `0`, removal is instant

---

## `spawn_prop`

Spawn a prop or non-humanoid figure mid-scene.

### Common keys
- `prop` — registry name
- `type` — prop type
- `figure_type` — optional override for figure-like props
- `rt` — fade-in time
- `on_head_of` — attach relative to a character’s head
- `on_torso_of` — attach relative to torso/chest

### Dodecahedron/Governor-specific keys
- `x`, `y`
- `color`
- `accent`
- `animate` — if `spin`, enable spin display
- `radius`
- `label`

### Dog-specific keys
- `x`, `y`
- `style`

### Notes
Standard props pass remaining keys through to `build_prop()`.

---

## `move_prop`

Move a prop to an explicit position.

### Keys
- `prop` — prop name
- `x` — target x
- `y` — target y
- `rt` — optional animation time; `0` means instant

### Notes
If the prop had a parent in the scene graph, explicit `move_prop` clears that parent relationship.

---

## `flash`

Temporary color flash on a prop, a character, or both.

### Keys
- `prop` — optional prop target
- `who` — optional character target
- `color` — flash color, default bright blue
- `duration` — hold time at flash color
- `rt` — fade-in and fade-out time

---

## `prop_color`

Change a prop’s color or state.

### Keys
- `prop` — target prop
- `color` — target color
- `rt` — transition time

### Notes
For GovernorGraph props, this may map colors into named states such as gold, amber, or dark.

---

## `elevator_open`

### Keys
- `who` or `prop` — elevator registry name
- `run_time` or `rt` — default 0.6

---

## `elevator_close`

### Keys
- `who` or `prop` — elevator registry name
- `fraction` — partial close fraction, default 1.0
- `run_time` or `rt` — default 0.6

---

## `open_lid`

### Keys
- `prop` — avatar pod name
- `run_time` or `rt` — default 0.6

---

## `close_lid`

### Keys
- `prop` — avatar pod name
- `run_time` or `rt` — default 0.6

---

## `prop_say`

Speech bubble for a prop, dog, or Governor.

### Keys
- `prop` — speaker prop name
- `text` — required text
- `hold` — hold time, default 1.4
- `font_size` — default 18
- `rt_in` — fade-in time, default 0.35
- `rt_out` — fade-out time, default 0.25
- `side` — bubble side, default `right`
- `style` — optional `os` for dashed-border bubble

### Notes
- consumes deferred camera moves like `say`
- delegates to GovernorGraph/DogGraph `say()` when appropriate

---

## `on_screen_text`

Centered text card overlay.

### Keys
- `text`
- `hold` — default 2.0
- `font_size` — default 20
- `color` — default `#e8c547`
- `rt_in` — default 0.4
- `rt_out` — default 0.3

---

## `caption`

Blocking caption card.

### Keys
- `text`
- `position` — `bottom`, `top`, `lower-third`
- `duration` — default 3.0
- `style` — `normal`, `italic`, `bold`
- `color` — text color
- `rt_in` — default 0.3
- `rt_out` — default 0.25

### Notes
This action blocks until its display cycle is finished.

---

## `overlay_caption`

Non-blocking caption that runs via updater.

### Keys
- `text`
- `position`
- `duration` — total visible time
- `style`
- `color`
- `rt_in`
- `rt_out`

### Notes
Unlike `caption`, this does not stop the action loop.

---

## `sound_cue`

Short diegetic label such as `RING!` or `KNOCK!`.

### Keys
- `label`
- `display` — bool, default true
- `hold` — default 0.6
- `rt_in` — default 0.15
- `rt_out` — default 0.20
- `x` — horizontal offset
- `y` — vertical offset

---

## `focus`

Dim and brighten cast members to direct audience attention.

### Keys
- `on` — list of names to brighten, or `["all"]`
- `dim` — list of names to dim, or `"all_others"`
- `opacity` — dimmed opacity, default 0.30
- `bright` — bright opacity, default 1.0
- `rt` — transition time, default 0.4

---

## `focus_reset`

Restore all active cast members to full opacity.

### Keys
- `rt` — default 0.4

---

## `parallel`

Play multiple actions at once.

### Keys
- `do` — list of sub-actions
- `rt` — run time for simple parallelized actions
- `rt_per_kf` — run time per locomotion keyframe when interleaving movement

### What works well in `parallel`
- `morph`
- `turn`
- `scale`
- `fade_out`
- locomotion plans such as `walk_to`, `run_to`, and `trot_to` via interleaving

### Limitations
`say` is **not** parallel-safe. Although the module docstring once listed it as such, `say` is absent from `_PARALLEL_OK` and its handler ignores `collect_anims` — it always fires sequentially via its own `self.play()` call. Place `say` outside any `parallel` block.

Other multi-step choreography (`wave`, `sit_down`, `stand_up`, `carry`) also degrades to sequential execution.

## 9. Actions delegated through `ACTION_REGISTRY`

Many core animation verbs are not implemented inline in `pam_player.py`; they are handed off to `pam.actions.ACTION_REGISTRY`.

That usually includes actions such as:

- `morph`
- `turn`
- `scale`
- `fade_out`
- `walk_to`
- `run_to`
- `walk_to_prop`
- `sit_down`
- `stand_up`
- `carry`
- `pick_up`
- `put_down`
- `group_translate`
- `express`
- `peel_from_hand`
- and other registry-defined verbs

For the manual, it is worth stating that **the player is both a dispatcher and a host runtime**. Not every action’s full parameter contract lives in this one file.

## 10. Camera metadata reference

When camera mode is active, the player consumes `shot_meta` dictionaries.

## `framing`

Supported values in the code:

- `wide`
- `medium`
- `medium-close`
- `close`
- `ots-left`
- `ots-right`
- `oneshot`
- `insert`

These map to internal frame widths and center heights.

## `move`

Supported values in the code:

- `static`
- `push`
- `pull`
- `pan-follow`
- `drift`
- `pan-up`
- `pan-down`
- `descend`
- `push-into`

## `subject`

Usually:
- a character key
- `ensemble`
- a prop name
- a scene-object name
- `governor` / `dodecahedron`

## 11. Extra camera parameters for special move types

## `pan-up`

### Keys
- `subject` — usually a building or vertical object
- `char_subject` — optional anchor character
- `rt` — tilt-up duration, default 2.5
- `rt_return` — tilt-back duration, default 1.8
- `hold` — hold at top, default 0.8
- `shear` — keystone amount, default 0.18
- `y_squeeze` — optional vertical squeeze factor

---

## `pan-down`

Uses normal framing and subject plus built-in timing.

### Effective key
- `rt` is taken from the internal move table; default 2.5 unless code is changed

---

## `descend`

### Keys
- `from_y` — start camera center y, default 4.0
- `to_y` — end camera center y, default -6.0
- `rt` — total travel time, default 10.0
- `rate` — `smooth`, `linear`, `rush_into`, `ease_in`, `ease_out`
- `bg_color` — optional background color at descent start

---

## `push-into`

### Keys
- `subject` — target prop or scene object
- `rt` — push duration, default 3.0
- `zoom_to_w` — final camera width, default 3.5
- `flash` — whether to use end flash, default true
- `rt_flash_in` — flash fade-in time, default 0.15
- `rt_flash_out` — flash fade-out time, default 0.20

## 12. What `pam_player.py` does not do

It is important to document the negative space too.

`pam_player.py` does **not**:

- define a traditional `argparse` CLI
- convert Fountain directly
- export Blender scenes
- define every action implementation inline
- own Manim’s quality flags or output options

Those responsibilities belong to other parts of the PAM toolchain.

## 13. Practical troubleshooting notes

## If nothing renders
Check these first:

1. `PAM_SCRIPT` points to a real JSON file.
2. You ran `manim ... pam_player.py PAMPlayer` with the scene name included.
3. The JSON parses successfully.
4. Your screenplay actually contains visible actions such as `fade_in`, `spawn_prop`, `caption`, or `on_screen_text`.

## If camera motion is wrong
Check:

1. `PAM_CAMERA_MODE` behavior.
2. whether `_subscene_marker` entries exist in the PAM JSON.
3. whether `PAM_PROMPTS` points at the matching prompts file.
4. whether the subject names in `shot_meta` match live character, prop, or scene-object names.

## If a character action is skipped
Common causes:

- `who` does not match a declared cast key
- the character was never faded in
- the action is registry-based and its handler lives in `actions.py`

## If a prop action is skipped
Common causes:

- the prop name does not exist in the registry
- the prop was removed earlier
- the prop type does not support the requested method, for example `open_lid` on a non-pod prop

## 16. Bottom line

For users, the most important distinction is:

- **Manim controls rendering options**
- **PAM environment variables control screenplay loading and camera behavior**
- **JSON actions control the actual animation**

That is the correct mental model for `pam_player.py`.
